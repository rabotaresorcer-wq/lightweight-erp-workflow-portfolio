# Case Notes

## Portfolio Positioning

This case is positioned as an operations and process design project, not only as a spreadsheet project.

The key point is the operating model: one event record becomes the source for CRM, pricing, client materials, operations, finance, and management reporting.

## Narrative Order

The repository starts with the business problem before showing the system:

1. Repeated data entry across multiple business layers.
2. One event record as the source of truth.
3. Structured workflow across CRM, quoting, deliverables, operations, finance, and reporting.
4. Visual proof through the nine final LinkedIn cards.
5. Business effect and future automation opportunities.

This order is intentional. A hiring manager should first understand why the system was needed, then see how the workflow solves the problem.

## Master Reference

The nine cards in `assets/linkedin-final/` are the final English LinkedIn version of the case.

They should be treated as a fixed visual reference:

- do not edit the card images in this repository without a separate decision;
- do not reorder them unless the portfolio narrative is intentionally changed;
- do not replace anonymized or synthetic values with real confidential data;
- keep derived versions separate from this master reference.
